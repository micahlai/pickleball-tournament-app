# Courtwave planning

Read the repository [AGENTS.md](../../../AGENTS.md), [status](../../../docs/project-status.md), and [open decisions](../../../docs/open-decisions.md) before changing plans.

Read the current authorization in AGENTS.md. The user authorized M0/M1 implementation, parallel work, and incremental commits on 2026-10-16. Keep later features behind their milestone gates; a completed foundation does not authorize M2–M6 or external provisioning/deployment.

Separate confirmed user decisions, source-PDF candidates, selected engineering recommendations, and unresolved requirements. Preserve the user's exact ambiguous wording when it matters. Ask for the missing business rule instead of choosing one.

When an answer arrives, update the requirements register, relevant spec, decision register, acceptance criteria, and status together. Keep source transcription historical: annotations may explain a superseding user answer, but do not rewrite what the PDF said.

Use [agent workflow](../../../docs/agent-workflow.md) for specialist handoffs only when delegation is authorized. Give each worker bounded ownership and carry the current scope restriction into its task.

For backend changes, consult [architecture](../../../docs/architecture.md). Start free-first, verify current provider limits before provisioning, and raise required spending to the user. A recommendation does not authorize an external account or deployment.

Finish with concrete paths changed, decisions still open, and what is actually ready. Do not claim a skill is loaded or an agent is configured merely because its Markdown exists.
